## [OpenAI 发布 GPT-6 Astra，其最强商业模型](https://openai.com/index/gpt-6-astra-next-generation-work) ⭐️ 9.0/10

OpenAI 发布了 GPT-6 Astra，称其为面向商业场景的最强模型，具备高级推理、计算机操作能力以及更强的写作与设计判断力。据维基百科，该模型于 2026 年 9 月 3 日先向获批用户开放，次日全面可用，此前因 2026 年 7 月的 Hugging Face 事件而推迟发布。 OpenAI 推出的这款新旗舰模型被定位为面向商业场景的最强模型，可能围绕推理与自主计算机操作重塑企业工作流，并加剧与 Anthropic 的 Claude 和 Google 的 Gemini 在智能体 AI 领域的竞争。它还是 OpenAI 首个在 Preparedness Framework 下达到网络安全能力“关键”级别的模型，标志着广泛部署的 AI 进入新的能力与风险层级。 OpenAI 表示 Astra 是其对齐程度最高的模型，在理解用户意图和模型行为方面有显著改进，让用户可以更放心地委派任务。GPT-6 Astra 系统卡指出，它是首个在 OpenAI Preparedness Framework 下达到网络安全能力“关键”级别的模型，这对企业部署而言是一个值得注意的警示。

rss · OpenAI Blog · 9月9日 11:00

**背景**: 大语言模型（LLM）是在海量文本数据上训练、能够生成并推理语言的 AI 系统；近期的“推理模型”加入了逐步思考机制，能提升准确率，但也会增加输出冗长度和延迟。“计算机操作”指 AI 模型能像人一样控制软件和浏览器，这一能力由 Anthropic 的 Claude 率先推出，随后 Google 的 Gemini 2.5 Computer Use 也加以采用。OpenAI 的 Preparedness Framework 是其内部安全评估体系，按网络安全等风险类别对模型分级，其中“关键”属于高严重性门槛。

## [Calif Research 发布 WeWorm：首个借助 AI 构建的微信通话零点击蠕虫](https://simonwillison.net/2026/Sep/10/calif-research/) ⭐️ 9.0/10

Calif Research 发布了 WeWorm 的演示，称其为首个通过微信通话在 iOS 和 Android 上传播的零点击蠕虫，受害者无需接听电话或与手机进行任何交互，账号即可被攻陷。该团队表示，他们借助 AI 在大约两天内发现了漏洞并编写出首个远程代码执行（RCE）利用程序，随后又用约一周时间构建出蠕虫。 这是移动安全领域的一次重大升级：一个无需用户交互即可自我传播的蠕虫理论上可能波及微信约 14 亿用户，而 AI 将原本需要数月的漏洞利用开发压缩到几天，标志着漏洞发现与武器化方式的范式转变。这为平台防御方和 AI 安全研究者都提出了紧迫问题：攻击能力如今可以被多快地制造出来。 即使受害者接听电话，漏洞利用依然成功，此时他们听不到任何声音；Calif 还演示了该蠕虫在三部测试手机之间传播。团队强调 AI 完成了大部分工作，人类只负责判断攻击目标以及如何安全测试，该研究于 2026 年 9 月 8 日作为演示而非真实攻击发布。

rss · Simon Willison · 9月10日 00:56

**背景**: 零点击漏洞利用是指无需用户任何操作即可攻陷设备，因此比需要打开文件或点击链接的攻击危险得多。蠕虫是一种能自我复制并自动在受害者之间传播的恶意软件，而远程代码执行（RCE）意味着攻击者可以在目标设备上运行任意代码。微信是一款拥有约 14 亿用户的中国即时通讯应用，其语音通话功能正是这项研究针对的攻击入口。

## [OpenAI 推出由 Codex Harness 驱动的托管 Agents API](https://openai.com/index/introducing-the-agents-api) ⭐️ 8.0/10

OpenAI 推出了 Agents API，这是一项托管服务，开发者只需一次 API 调用并指定任务、模型、工具和运行环境，即可构建并启动云端智能体。该服务由 Codex harness 驱动，目前已面向所有开发者开放公开测试版，除常规用量费用外不收取额外费用。 这是一次平台层面的布局，降低了构建自主云端智能体的门槛，开发者可以把编排、会话管理和上下文处理交给 OpenAI，而无需自行搭建这些基础设施。这可能加速智能体类 AI 应用的普及，并加剧提供托管智能体运行时的云厂商之间的竞争。 Agents API 运行 Codex harness，并代为处理自动上下文压缩、会话管理和编排，让团队可以专注于智能体自身的独特价值。它与托管沙箱（hosted sandboxes）一同提供，按常规用量计费，而不是单独收取 API 费用。

rss · OpenAI Blog · 9月10日 00:00

**背景**: 智能体 harness 是驱动 AI 智能体的可复用循环：它向模型提供上下文、执行工具调用，并跨多轮管理状态。OpenAI 的 Codex harness 最初与用 Rust 编写的开源 Codex CLI 相关联，提供了这些约定和上下文工程模式。Agents API 把该 harness 封装为托管云服务，开发者因此不再需要自行运行智能体循环或会话基础设施。

Farid Zakaria 发布了 trynix.dev，这是一个由 qemu-wasm 驱动的 x86_64 Linux 虚拟机，完全在浏览器中运行，并可通过类似 https://trynix.dev/?pkg=python3%403.6.2 的 URL 地址启动过去 13 年内的任意 Nix 包。他还发布了 trynix-preview，这是一个 GitHub Action，会在拉取请求下评论一个链接，让审查者无需任何服务器即可直接在浏览器中启动该 PR 的构建。 这让历史版本和可复现的软件环境可以通过一个 URL 即时访问，无需安装 Nix 或配置服务器就能检查或测试某个包。它可能显著改变 Nix 用户、代码审查者以及任何需要复现旧构建的人的工作流程，同时展示了基于 WebAssembly 的模拟技术已经发展到何种程度。 该虚拟机基于 ktock/qemu-wasm 构建，后者将 QEMU 编译为 WebAssembly，并采用混合方案：只有被频繁执行的翻译块才会编译为 Wasm，其余部分则通过 TCI 解释器运行。包通过 URL 参数寻址，而 trynix-preview 动作将这一能力集成到 GitHub 拉取请求审查中，且不需要任何后端基础设施。

rss · Simon Willison · 9月10日 23:44

**背景**: Nix 是由 Eelco Dolstra 于 2003 年创建的纯函数式包管理器，强调可复现和声明式的构建，因此在一个机器上能正常工作的包在另一台机器上也应表现一致。QEMU 是通用机器模拟器，而 qemu-wasm 是将它编译为 WebAssembly 的项目，使完整的操作系统能够在浏览器标签页内运行。trynix.dev 将这两者结合，让浏览器托管的 Linux 虚拟机能够启动由 URL 指定的特定 Nix 包。

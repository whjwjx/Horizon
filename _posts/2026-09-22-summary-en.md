## [NASA Cancels Mars Sample Return Mission](https://www.science.org/content/article/nasa-s-mars-sample-return-mission-dead) ⭐️ 8.0/10

NASA has effectively cancelled its Mars Sample Return (MSR) mission, a joint campaign with the European Space Agency, after costs ballooned to an estimated $8–11 billion and the return date slipped to around 2040. The decision was reportedly finalized under acting administrator Jared Isaacman, who concluded the existing architecture was unsustainable. The cancellation is a major setback for planetary science, as MSR was the highest-priority solar system exploration goal for decades and would have enabled detailed analysis of Martian rocks for signs of ancient life. It also hands a potential first-mover advantage to China's Tianwen-3 mission, which aims to return Mars samples around 2031, shifting the geopolitical balance in space exploration. The mission relied on NASA's Perseverance rover, which has already cached samples on Mars, and would have used a European-built Earth Return Orbiter and a NASA-led Sample Retrieval Lander. Critics argue JPL designed the campaign around legacy rockets like Ariane 64 rather than lower-cost commercial options such as Starship or New Glenn, and that the architecture was overly complex.

**Background**: Mars Sample Return is a multi-mission concept to collect rock and dust samples on Mars and bring them to Earth, where they can be studied with far more capable laboratory instruments than any rover can carry. NASA's Perseverance rover, which landed in 2021, has been sealing samples in tubes for this purpose. The mission was approved in 2022 as a NASA-ESA collaboration, but repeated cost increases and delays led to its cancellation in 2026. China's Tianwen-3 mission, planned for launch in 2028, aims to return samples around 2031.

## [TypeSafe AI's Jev Introduces 'System One' Decision Models](https://simonwillison.net/2026/Sep/21/jev/) ⭐️ 8.0/10

TypeSafe AI unveiled Jev, its first 'System One' model, which accepts text input but returns typed probabilistic outputs—confidence scores for yes/no questions, probability distributions over choices, and numeric ratings—instead of generated text. The model charges only for input at $0.042 per million tokens, making it cheaper than OpenAI's GPT-5 Nano, and evaluates many questions in parallel. This introduces a new model category optimized for classification, ranking, and prioritization tasks rather than text generation, potentially offering a much faster and cheaper alternative for applications like spam detection and search reranking. It signals a possible paradigm shift in how LLMs are applied, moving from conversational text output toward typed decisions that software can consume directly. Jev supports three question types: 'Noul' yes/no questions (named after the Bernoulli distribution), choice questions returning a probability distribution across options, and score questions returning a floating point value along a numeric range. A notable limitation is that it is a black box—it returns only numbers with no explanation, raising concerns about hidden bias, especially in high-stakes uses like ranking job applicants.

rss · Simon Willison · Sep 21, 23:09

**Background**: System One models are a new class of AI models built to make fast, structured decisions that software can use directly, as opposed to standard LLMs that generate free-form text. Jev is developed by TypeSafe AI, a San Francisco-based company founded in 2024, and was released in limited early access. The name 'System One' references dual-process theory in psychology, where fast, intuitive thinking is called System 1, contrasting with slower deliberative reasoning.

## [Cloudflare Python Workers reach general availability after two-year preview](https://simonwillison.net/2026/Sep/21/cloudflare-python-worker/) ⭐️ 7.0/10

After a two-year preview period, Cloudflare has announced that Python Workers are now generally available, making Python a first-class, fully supported language on the Cloudflare Developer Platform. The implementation runs Python compiled to WebAssembly via Pyodide inside Cloudflare's V8-based workerd runtime. This is a significant milestone for serverless Python developers, who can now deploy Python workloads on Cloudflare's edge platform with production-level support rather than experimental preview status. It also signals Cloudflare's deeper investment in the Python ecosystem, with the release credited to Pyodide core maintainers Gyeongjae Choi and Hood Chatham. The platform has documented limitations, most notably that both multiprocessing and threading are non-functional inside the WebAssembly VM. Local development is handled by the pywrangler tool (published on PyPI as workers-py), which runs a full local simulation of the stack using a 123MB workerd binary that executes Pyodide in WebAssembly within V8.

rss · Simon Willison · Sep 21, 22:25

**Background**: Pyodide is a port of CPython to WebAssembly/Emscripten, originally created in 2018 by Michael Droettboom at Mozilla, that lets Python run in browsers and Node.js and supports many packages with C, C++, and Rust extensions such as NumPy, pandas, and scikit-learn. workerd is Cloudflare's open-source JavaScript/Wasm server runtime, sharing most of its code with the runtime that powers Cloudflare Workers. WebAssembly's original MVP did not include threading constructs, and multithreading support remains experimental across many toolchains, which explains why threading and multiprocessing are unavailable in this environment.

## [Simon Willison defends MCP against 'always a bad idea' critique](https://simonwillison.net/2026/Sep/20/hn-49779718/) ⭐️ 7.0/10

In a comment on the Hacker News thread "MCP was always a bad idea?", Simon Willison argued that the Model Context Protocol still delivers substantial value today, even though full-blown terminal agents like Claude Code, Codex, Meta Muse, and OpenClaw can simply call APIs directly. He listed four concrete benefits MCP provides: control over which external services an agent can reach, authentication that keeps API keys away from the agent, a sensible UI for connecting and authenticating services, and strong audit logging. The debate matters because many developers are concluding that MCP is obsolete now that terminal-based coding agents can hit APIs directly, and Willison's rebuttal reframes MCP as the infrastructure for building safer, more controlled agent products rather than just a tool-calling convenience. This affects anyone building agent platforms that need permissioning, credential isolation, and compliance-grade logging. Willison concedes that MCP offers almost no advantage for a "full-blown terminal agent" with unfettered internet access, since such agents can just call APIs directly; the value appears only when you want something less "YOLO" than that. The four capabilities he highlights — access control, key-isolating authentication, a connection UI, and audit logging — are exactly the enterprise-grade concerns that raw API calls leave to each developer to reimplement.

rss · Simon Willison · Sep 20, 20:24

**Background**: The Model Context Protocol (MCP) is an open standard and open-source framework introduced by Anthropic in November 2024 to standardize how AI systems such as large language models integrate and share data with external tools, systems, and data sources. Terminal AI agents like Claude Code run locally in the terminal, understand a codebase, edit files, and run commands, often talking directly to model APIs without a backend server. The Hacker News thread questioned whether MCP was ever a good design, prompting Willison's response.

## [OpenAI Enhances Prompt Caching for GPT-6](https://openai.com/index/better-prompt-caching-for-gpt-6) ⭐️ 8.0/10

OpenAI has introduced improved prompt caching for GPT-6, featuring higher cache hit rates, new diagnostics tools, explicit cache breakpoints, and controls designed to reduce latency and costs. The update also includes a refreshed prompt caching guide explaining how developers can choose which prompt prefixes to reuse. Prompt caching is one of the highest-leverage cost and latency optimizations for teams building on large language models, and these improvements directly affect developers using the GPT-6 API. Higher hit rates and better diagnostics can significantly lower token costs and response times for production applications with long, repeated prompts. Explicit cache breakpoints let developers choose which prompt prefixes to reuse, and when no explicit breakpoints are placed, the request does not use prompt caching or create cache writes. A Prompt Caching Dashboard monitors cache read hit rates, while the Prompt Cache Diagnostics tool helps diagnose cache misses and improve reuse.

rss · OpenAI Blog · Sep 22, 21:00

**Background**: Prompt caching reduces latency and token costs for long prompts by storing and reusing the processed prefix of a prompt across requests, so the model does not need to reprocess identical content each time. It is enabled by default for supported OpenAI models, and best practice is to keep the cacheable prefix identical across requests while placing user-specific content at the end. Cache hit rate is a key production metric: one team reported raising it from 23% to 71% simply by moving a user-context block out of the system prompt.

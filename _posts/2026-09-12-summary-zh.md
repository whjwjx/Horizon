## [trynix.dev 借助 qemu-wasm 在浏览器中运行任意 Nix 包](https://simonwillison.net/2026/Sep/10/trynix/) ⭐️ 8.0/10

Farid Zakaria 发布了 trynix.dev，它利用 qemu-wasm 在浏览器中完整启动一台 x86_64 Linux 虚拟机，并能加载过去 13 年内的任意 Nix 包。这些包可通过 URL 直接寻址，例如访问 https://trynix.dev/?pkg=python3%403.6.2 并点击“Load”，即可获得一个运行 2017 年 Python 3.6.2 的交互式 shell。 这让可复现环境可以仅凭一个链接即时分享，无需服务器或本地安装，可能改变演示、调试和 CI 工作流。配套的 GitHub Action 名为 trynix-preview，它会在拉取请求上评论一个可启动链接，让审查者直接在浏览器中运行该 PR 的构建结果。 该虚拟机由 ktock/qemu-wasm 驱动，这是 QEMU 移植到 WebAssembly 的实验性版本，支持 TCG JIT 编译、网络和挂载，并能运行未经修改的 Linux 客户机。由于一切都在浏览器客户端执行，不需要浏览器之外的代理服务，但性能取决于浏览器的 WebAssembly 能力。

rss · Simon Willison · 9月10日 23:44

**背景**: Nix 是由 Eelco Dolstra 于 2003 年开发的纯函数式包管理器，它将每个包安装到唯一的内容寻址位置，从而使构建可靠且可复现。QEMU 是一款可虚拟化多种 CPU 架构的全系统模拟器，而 qemu-wasm 将其编译为 WebAssembly，使真正的 Linux 虚拟机能在浏览器标签页中运行。可复现构建旨在让相同源码和构建环境产出的二进制文件逐位一致，这正是 Nix 提供的保证，也是 trynix.dev 所利用的特性。

## [Shopify 放弃 React Native，回归原生 Swift 与 Kotlin](https://simonwillison.net/2026/Sep/10/shopify-react-native/) ⭐️ 8.0/10

Shopify 宣布将其移动应用从 React Native 迁回分别使用 Swift（iOS）和 Kotlin（Android）的原生代码库，推翻了 2020 年做出的决定。该公司明确表示，AI 编码代理是双平台维护成本不再成为决定性因素的原因。 这是一个值得关注的行业信号：AI 编码代理正在重塑移动工程策略，可能让原生开发对曾为节省成本而采用跨平台框架的大型公司重新变得可行。这可能会影响其他在 React Native 与完全原生方案之间权衡的组织。 Shopify 维护着三个重要的 React Native 库——react-native-skia、flash-list 和 restyle；该公司表示前两个正在寻找新归宿，而 restyle 因用户基数较小将于 2026 年底归档。Shopify 充分肯定了 React Native 在其使用的六年里是一个优秀的平台。

rss · Simon Willison · 9月10日 21:11

**背景**: React Native 是 Meta 开发的开源 UI 框架，允许开发者使用 JavaScript 和 React 为 iOS 和 Android 构建应用，从而减少为每个平台编写单独代码的需求。原生开发则意味着为 iOS 用 Swift、为 Android 用 Kotlin 编写平台专属代码，性能更好、平台集成更佳，但需要维护两套代码库。Shopify 最初在 2020 年转向 React Native，是为了避免重复构建相同功能，并让开发者能够跨技术栈工作。
